# AGENTS.md

This file provides guidance to coding agents (e.g. Claude Code, claude.ai/code) when working with code in this repository.

## Repository purpose

The Hugo source for the Virtual Secrets product site, [virtual-secrets.dev](https://virtual-secrets.dev). Documentation pages are *aggregated* from other Virtual Secrets repos (the docs repo, installer, etc.) at build time — this repo holds the shell (layouts, theme, marketing content, configuration), and `hugo-tools` pulls the rest into `content/docs/` before Hugo renders the site.

Hosted on Firebase Hosting (`firebase.json`). `package.json` exists only to install PostCSS / autoprefixer / fs-extra for asset processing — there is no JS app to build.

## Architecture

- `config.yaml` / `config.dev.yaml` — Hugo config. `theme: hugo-product-theme` (vendored under `themes/hugo-product-theme`). The `params:` block is the shared cross-product config (`product_key: virtualsecrets`, sibling domain URLs, social links, search API key, etc.).
- `content/` — marketing pages: `datasheet/`, `docs/`, `meet-expert/`. `content/docs/` is populated by `make docs` from the docs aggregator; do not hand-edit aggregated pages — fix the upstream repo instead.
- `data/` — JSON config consumed by templates (`data/config.json` is rewritten by `make set-assets-repo`).
- `layouts/`, `archetypes/`, `static/`, `resources/` — standard Hugo dirs. `static/files/` is wiped of `cluster-api*`, `*-marketplace` content by `make docs` / `make assets` — those exclusions are intentional, do not re-add.
- `themes/hugo-product-theme/` — the shared AppsCode product theme (separate git repo, vendored here).
- `hack/scripts/` — release/CI helpers.
- `bin/hugo-tools` — downloaded by the `hugo-tools` Make target; runs the docs aggregator (`docs-aggregator`).
- `firebase.json` — hosting + redirects. `make set-version VERSION=…` rewrites doc redirects to point at a versioned path; `make set-assets-repo ASSETS_REPO_URL=…` rewrites `data/config.json`.
- `process-css.js`, `postcss.config.js` — PostCSS pipeline for theme CSS.
- `public/` — Hugo build output; produced by `make gen` / `make gen-prod`, deployed to Firebase. Do not commit edits here.

Note: some metadata still references the sister "kubeobj" project (`package.json` name/URLs, the `--fm-replacements product_kubeobj_=docs_,/products/kubeobj/=/docs/` flag passed to `hugo-tools`). That is the docs aggregator's source-folder convention, not a copy-paste mistake.

## Common commands

You need Hugo (extended) installed locally; the legacy `README.md` pin to v0.57.2 is out of date — use a recent extended Hugo.

- `npm install` — install PostCSS/autoprefixer dev deps (run once).
- `make run` — `hugo server --config=config.yaml`; live-reload dev server on http://localhost:1313.
- `make docs` — run the docs aggregator (pulls docs from sibling repos into `content/docs/` and `static/files/`), then prune the unwanted `cluster-api*` / `*-marketplace` directories. Requires network access to GitHub.
- `make docs-skip-assets` — same as `make docs` but skips static asset copying. Useful for fast iteration.
- `make assets` — only copy assets (no markdown).
- `make gen` — clean `public/` and run `hugo --config=config.yaml`. Dev build.
- `make gen-prod` — clean `public/` and run `hugo --minify --config=config.yaml`. Production build.
- `make qa` — `make gen` then `firebase use default && firebase deploy` (deploys to QA/staging Firebase project).
- `make release` — `make gen-prod` then deploy to the production Firebase project.
- `make check-links` — run `liche` against the built `public/` to verify links.
- `make set-version VERSION=v1.2.3` — rewrite `firebase.json` doc-version redirects (used during a release cut).
- `make hugo-tools` — fetch the `appscodelabs/hugo-tools` binary into `bin/`. Other targets call this automatically.

## Conventions

- Hugo + Firebase Hosting; **not** a Node/JS app despite the `package.json`.
- The product theme is shared across many AppsCode sites; treat `themes/hugo-product-theme/` as upstream — push fixes there, then re-vendor.
- Aggregated docs (`content/docs/**`, much of `static/files/**`) are regenerated by `make docs`. **Do not** commit hand-edits in those paths — change the upstream repo and re-run aggregation. The Makefile actively wipes `cluster-api*` / `*-marketplace` directories from `static/files/` on every aggregation; don't try to keep them.
- The site config (`config.yaml`) intentionally lists every sibling AppsCode product domain — keep them alphabetized and consistent with other AppsCode product sites.
- License: Apache-2.0 (per `package.json`).
- Sign off commits (`git commit -s`).
- `pglite-debug.log` and `hugo_stats.json` are local-only artifacts; do not depend on them.
